# GEPER corporate website

Corporate/informational site for GEPER. Astro 7 · Tailwind v4 (compiled) · Three.js (npm, lazy-loaded on the home page only).
Production runs on Cloudflare Workers: the pages are static assets, and a small Worker answers `/api/contact`.

## Commands

```
npm install
npm run dev          # local dev server (pages only; the contact API is not running here)
npm run dev:worker   # build, then run pages + API locally with wrangler (http://localhost:8787)
npm run check        # astro check: type-checks .astro, .ts and the Worker
npm test             # unit tests for the contact API and the Worker router (node --test, no network)
npm run build        # check + test, then astro build → dist/, scripts/gen-headers.mjs, scripts/verify-dist.mjs
npm run smoke        # post-deploy checks against https://geper.in (or pass a base URL); sends no email
npm start            # Node server for hosts that run a process (e.g. Render): serves dist/ + /api/contact
```

`npm run build` fails if the type check, the tests or the post-build guard fail, and Workers Builds runs
`npm run build`, so a broken build never deploys. `verify-dist` rejects Stitch remnants, forbidden claims, broken links,
canonical URLs that differ from the served URL, a missing social image, sitemap, robots.txt or favicon.ico, and a
missing Content-Security-Policy.

Routes: `/`, `/technology`, `/research`, `/platform`, `/about`, `/contact`, `/privacy`, `/terms`, `/message-sent`
(no-JavaScript form confirmation, noindex), plus `/sitemap.xml` and `/robots.txt`. Unknown paths get `404.html` with status 404.
Pages are built as files (`about.html`) and served without the extension; canonical URLs use the extensionless form.

## Environment variables (`.env`, see `.env.example`)

| Variable | Required | Purpose |
|---|---|---|
| `PUBLIC_SITE_URL` | recommended | Origin for canonical and Open Graph URLs, sitemap and robots.txt (default `https://geper.in`) |
| `PUBLIC_CONTACT_EMAIL` | recommended | Email shown on Contact and used by the mailto fallback |
| `PUBLIC_CONTACT_ENDPOINT` | optional | Contact API URL. Empty → the bundled Worker route `/api/contact` |
| `PUBLIC_TURNSTILE_SITE_KEY` | optional | Public Turnstile key. Default is the production key in `src/data/site.ts`; empty hides the widget |
| `PUBLIC_PRIVACY_UPDATED` / `PUBLIC_TERMS_UPDATED` | optional | "Last updated" dates on the legal pages (defaults in `src/data/site.ts`) |
| `PUBLIC_ANALYTICS_SRC` | optional | Script URL injected in `<head>`. Empty → no analytics. Its origin is added to the CSP automatically |

Values are read at build time.

## Security headers

`scripts/gen-headers.mjs` writes `dist/_headers` after every build. Workers Static Assets applies it to every static
response (the file itself is not served), and `server.mjs` reads the same file, so both hosts send the same headers:
HSTS, a Content-Security-Policy whose `script-src` lists a SHA-256 hash for each inline script Astro emitted (no
`'unsafe-inline'` for scripts), `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`,
`Cross-Origin-Opener-Policy`, and `immutable` caching for the fingerprinted `/_astro/` files. Responses generated by the
Worker (`/api/*`) set their own headers in `worker/contact.ts`.

HTTP → HTTPS redirection is the Cloudflare zone setting "Always Use HTTPS" (on).

## Contact backend (Cloudflare Worker + Static Assets + Resend + Turnstile)

`worker/index.ts` routes `POST /api/contact` to `worker/contact.ts`, which checks Turnstile and emails enquiries via Resend.
All pages are served as static assets from `dist/` (see `wrangler.jsonc`); only `/api/*` runs Worker code. An unexpected
exception is answered with JSON `500 {"error":"internal_error"}` and logged (Workers Logs is enabled in `wrangler.jsonc`).

Server-side env vars (Worker → Settings → Variables and Secrets, or `wrangler secret put NAME`; locally `.dev.vars`):
`RESEND_API_KEY` (secret, required), `TURNSTILE_SECRET_KEY` (secret; when set, every submission must carry a valid token),
`CONTACT_TO` (default `contact@geper.in`), `CONTACT_FROM` (default `GEPER Website <onboarding@resend.dev>`; production is
configured as `GEPER Website <website@notify.geper.in>` in `wrangler.jsonc`), `ALLOWED_ORIGINS` (optional).
The Resend key must be allowed to send from `notify.geper.in`.

The mail host rejects messages sent from outside servers that claim to be from an `@geper.in` address (`554 internal domain use`).
Always send from the `notify.geper.in` subdomain; the configured sender is `website@notify.geper.in`.

Local test (site + API): `npm run mock:resend` in one terminal, then `PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA npm run dev:worker`
→ http://localhost:8787/contact, with a git-ignored `.dev.vars` containing:

```
RESEND_API_KEY=re_mock
RESEND_API_URL=http://127.0.0.1:8799/emails
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA
TURNSTILE_VERIFY_URL=http://127.0.0.1:8799/siteverify
```

(`1x00…AA` are Cloudflare's always-pass Turnstile test keys.) Never set `RESEND_API_URL` or `TURNSTILE_VERIFY_URL` in production.

Deploy: Workers Builds (Git) with build command `npm run build` and deploy command `npx wrangler deploy`, or `npm run deploy`.
The Worker name in `wrangler.jsonc` (`geper-website`) must match the Worker in the dashboard. After a deploy, `npm run smoke`.

Node hosting (alternative): `npm run build && npm start` serves the same site and API from `server.mjs` (Node ≥ 22.18).
Set the same server-side variables in the host's environment. It redirects `.html`/trailing-slash URLs to the canonical
URL with 301, compresses text responses, applies `dist/_headers`, and rate-limits by the right-most `X-Forwarded-For` entry.

## Contact endpoint contract

`POST {PUBLIC_CONTACT_ENDPOINT}` with `Content-Type: application/json`:

```json
{ "name": "…", "email": "…", "organization": "… (optional)", "inquiryType": "research|platform|data|press|general",
  "message": "…", "website": "", "submittedAt": "ISO-8601", "submissionId": "uuid", "turnstileToken": "…" }
```
`website` is a honeypot: when it is non-empty the API answers success and sends nothing. `submissionId` becomes Resend's
idempotency key, so a retried attempt cannot email twice.

Responses the frontend handles:

| Status | Body | Frontend behaviour |
|---|---|---|
| `202` (or `200`) | `{ "id": "…" }` optional | success state, form cleared, reference shown |
| `400` | `{ "errors": { "email": "msg", … } }` | field errors shown inline |
| `403` | `{ "error": "verification_failed" }` | "could not confirm a person sent this" + mailto fallback link |
| `429` | `{ "error": "rate_limited" }` | "try again later" + mailto fallback link |
| other / network / 15 s timeout | — | error state + mailto fallback link carrying the drafted message |

Without JavaScript the form posts `application/x-www-form-urlencoded` to the same endpoint. The API then answers with
plain HTML pages instead of JSON, and a successful post gets `303 → /message-sent`. Nothing is ever placed in a URL.
Because Turnstile needs JavaScript, a no-JS post is refused with a page that gives the email address.

## Content

All copy lives in `src/data/content.ts` and `src/data/site.ts`. Status badges accept only
`in-development | planned | active | out-of-scope`. `research.publications`, `technicalNotes` and `validation`
are empty arrays that render honest empty states — add entries only for public material.
